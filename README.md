# rematch-observer

Rematch の画面を読んで、**試合の結果とゲームコードを大会運営 Bot に自動で渡す**常駐ソフトです。

選手が 1 対戦のあいだにゲームの外で押す回数は、前後半制で 5〜8 回あります。
そのうち**ルームコードの入力と結果の報告は、どちらもゲームの画面に出ています。**
それを読んで代わりに送るのがこのソフトです。

**手で入力する経路はそのまま残ります。** これは代替ではなく、速くするためのものです。

---

## 何を送り、何を送らないか

**送るのは数字だけです。**

| 送るもの | |
| --- | --- |
| ゲームコード | 6 桁の数字 |
| 結果 | ホーム側とアウェイ側のゴール数 |
| 送り主 | 設定に書いた自分の Discord の id |
| 対戦 id | 運営が観戦するときだけ（対戦表の `#12` の数字） |

| **送らないもの** | **なぜ** |
| --- | --- |
| **画像** | スクリーンショットも切り抜きも一切送りません。**個人情報が外に出る経路を塞ぐ唯一の手段です** |
| **選手名** | 照合に使わないので、送れば個人情報が増えるだけです |
| **チーム名** | そもそもゲームの画面に出ていません |
| **試合番号** | Bot が記録済みの次を埋めます |
| **どちらが「自分」か** | ホーム／アウェイの絶対値で送ります |

**撮るのはゲームのウィンドウだけです。デスクトップ全体は撮りません。**

---

## アンチチートと規約について

Rematch のアンチチートは **Easy Anti-Cheat** です。**外部プロセスからの画面キャプチャは、
配信ソフトと同じ扱いで妨げられません**（2026-09-08 時点で確認）。

**このソフトは次のどれもしません。**

- ✗ ゲームのプロセスへの注入・DLL の読み込み
- ✗ メモリの読み書き
- ✗ 入力の自動送信
- ✗ オーバーレイの描画

使っているのは **Windows.Graphics.Capture**（OBS などの配信ソフトと同じ API）だけです。

⚠ **観戦視点から得た情報を、試合中の当事者に返してはいけません。**
アンチチートに掛からなくても、明確に不当な優位になります。

---

## コード署名について

**このソフトには現時点でコード署名がありません。**
初回の起動時に **Windows SmartScreen の警告**が出ます。

**署名の代わりに、ソースを全部公開しています。**
画面を撮るソフトを入れてもらう以上、**中身を読んで確かめられることが唯一の根拠です。**
`src/` を読めば、何を撮り、何を送っているかは全部確かめられます。

## 使いかた

### 1. 入手する

[Releases](https://github.com/setopic/rematch-observer/releases) から
`rematch-observer.exe` を落とします。**単一の exe で、.NET の導入は要りません。**

### 2. 設定する

```
rematch-observer.exe config-init
```

`%APPDATA%\rematch-observer\config.json` ができます。最低限、次の 2 つを書きます。

| 項目 | 何を書くか |
| --- | --- |
| `webhookUrl` | 運営から渡される Discord の Incoming Webhook の URL |
| `senderDiscordId` | **自分の** Discord のユーザー id（開発者モードでコピーできます） |

**運営として観戦するときは `matchId` も要ります。**
運営はどのチームにも所属していないので、**どの対戦を見ているかを Bot に教えられません。**
対戦表に `#12` の形で出ている数字を書いてください。

⚠ **`webhookUrl` は秘密です。** これを知っている人は誰でも観測を送れます。
人に見せないでください。漏れたら運営に言って作り直してもらってください。

**選手は `matchId` を空のままで構いません**（Bot が所属から対戦を引きます）。

### 3. テンプレートを作る

**ラベルの照合には画像が要ります。** 画面の解像度や UI の版が違うと作り直しが要ります。
運営が配る `templates/` があるならそれを exe と同じ場所に置いてください。
自分で作るなら下の「テンプレートの作りかた」を見てください。

### 4. 動かす

```
rematch-observer.exe check     設定とテンプレートが揃っているかを見る
rematch-observer.exe watch     常駐する（Ctrl+C で終わる）
```

**最初は `--dry-run` を付けてください。** 送らずに本文だけ出します。

```
rematch-observer.exe watch --dry-run
```

## テンプレートの作りかた

**読んでいる場所は 3 つだけです。**

| 読むもの | どこ |
| --- | --- |
| ホームのゴール | `ホーム` セクションの `合計マッチ数` 行の **`ゴール` 列** |
| アウェイのゴール | `アウェイ` セクションの同じ場所 |
| ゲームコード | チーム選択画面の `ゲームコード:` の右（6 桁の数字） |

⚠ **`得点` 列を読んではいけません。** 同じ表にありますが、4000 のような別の指標です。
**列名がドメインの用語と一致しているのに意味が違います。**

⚠ **ヘッダの大きな数字を位置で読んではいけません。**
選手の画面は左が自分のチーム、運営の観戦は左がホームで、**視点で入れ替わります。**

⚠ **配信のオーバーレイを参考にしないでください。**
配信にはチーム名や「前半 / 後半」のタブが出ますが、**どちらもゲームの画面にはありません。**
OBS が足しているものです。

### 手順

**1. 結果の画面を出したまま 1 枚撮ります。**

```
rematch-observer.exe capture --out result.png
```

**2. 画像を開き、切り出す場所の座標を調べます**（ペイントなどでかまいません）。

**3. ラベルを切り出します。**

```
rematch-observer.exe crop --in result.png --rect 120,340,90,32 --out templates/label-home.png
rematch-observer.exe crop --in result.png --rect 120,700,110,32 --out templates/label-away.png
rematch-observer.exe crop --in result.png --rect 240,420,160,30 --out templates/label-total-matches.png
rematch-observer.exe crop --in result.png --rect 800,380,80,28  --out templates/label-goals.png
```

**4. 数字を 0〜9 まで切り出します**（`templates/digit-0.png` 〜 `digit-9.png`）。
画面のどこかに出ている数字から 1 つずつ取ってください。
**同じ画面・同じ大きさの数字から取ることが大事です。**

**5. 基準の高さを書きます。** `crop` が撮った画面の高さを教えるので、
`templates/templates.json` の `referenceHeight` をその値にします。

**6. 当たるかを見ます。**

```
rematch-observer.exe match --in result.png    どのラベルがどこに当たるか
rematch-observer.exe read  --in result.png    実際に読んだ値
```

**`read` が正しい数字を出すまで直します。**
当たらないときは、**余白を含めすぎていないか**を疑ってください。

### ゲームの UI が変わったら

**直すのはテンプレート画像で、コードではありません。**
`match` で当たらなくなったラベルを撮り直してください。

⚠ **読めなくなったときは、静かに間違えるのではなく何も送りません。**
`watch` を動かしても何も起きなくなったら、まず `read` で確かめてください。

## Bot に送るメッセージの形

⚠ **この節は [`CON-09`] の写しです。写しは CON-09 とここの 2 か所までで、
食い違ったときは CON-09 が正です。**（CON-09 は運営のリポジトリにあり、公開されていません）

**Discord の Incoming Webhook に、1 つの観測につき 1 通、1 行の平文を POST します。**

```
<@BOT> code  <送り主> <コード> [<対戦 id>]
<@BOT> score <送り主> <ホームのゴール> <アウェイのゴール> [<側>] [<対戦 id>]
```

```
<@1539187275068473434> code 123456789012345678 330787
<@1539187275068473434> score 123456789012345678 4 0 home
<@1539187275068473434> score 987654321098765432 4 0 - 12
```

- **空白区切り。`-` は「無い」を表す。**
- **`<側>` は `home` / `away` / `-`。** 運営の観戦では縁取りが出ないので `-` になる
- **ゴール数は 0 以上の整数。勝者は送らない**（ゴール数から導かれる）
- **本文の上限は 300 文字**（メンションを外した部分で数える）

⚠ **本文の先頭に Bot へのメンションを置きます。飾りではありません。**
これが無いと **Bot に本文が届きません**（Bot が特権インテントを使っていないため）。

⚠ **`allowed_mentions` でメンションを抑制してはいけません。**
抑制するとメンションとして数えられず、やはり本文が届きません。

⚠ **同じゲームコードを再送してはいけません。**
Bot 側がコードを入れ直すたびに**両チームの準備完了を白紙に戻します。**
このソフトは**値が変わったときだけ送ります。**

### 形を変えるときの決まり

- **既存の項目を壊さない。足すなら末尾に足す**
- **知らない項目は無視する**（新しい形が古い Bot に届いても捨てられるだけにする）
- **形を変えるなら種類の名前を変える**（`score2` のように）。同じ名前で意味を変えない

**観測ソフトは選手の PC にあり、Bot はサーバーにあります。片方だけが古いまま動きえます。**

---

## 送ったものがどう扱われるか

- **Bot は専用のチャンネル 1 本だけを見ます。** 未設定のサーバーでは何も起きません
- **登録された Webhook からの投稿だけを認めます**
- **送り主が運営ロールを持つか、その対戦の当事者でなければ捨てられます。**
  **メッセージの中で「自分は運営だ」と名乗ることはできません**
- **先に届いた観測が入ります。** 運営でも選手でも変わりません
- **記録には由来（人 / 選手の観測 / 運営の観測）が残ります**
- **運営の確定は従来どおり必要です。** 自動で確定まで進むことはありません

⚠ **誤検出への防御は事後の監査だけです。**
まとめての確定は由来で分けないので、**入った誤りは確定では止まりません。**
だからこのソフトは、**同じ値が続けて読めるまで送りません**（`stableReads`）。

## 設定の項目

| 項目 | 既定 | 何をするか |
| --- | --- | --- |
| `webhookUrl` | （空） | 送り先。**秘密** |
| `botUserId` | `1539187275068473434` | メンションする相手 |
| `senderDiscordId` | （空） | 自分の Discord の id |
| `matchId` | （無し） | 見ている対戦。**運営には要る** |
| `processName` | `Rematch` | 撮る相手のプロセス名 |
| `windowTitle` | （無し） | 絞り込むときだけ |
| `pollIntervalMs` | `1500` | 何ミリ秒ごとに見るか |
| `templatesDir` | `templates` | テンプレートの置き場所 |
| `labelThreshold` | `0.80` | ラベルの照合の厳しさ。**下げると静かに間違える** |
| `digitThreshold` | `0.85` | 数字の照合の厳しさ |
| `stableReads` | `3` | 同じ値が何回続いたら送るか |
| `cellWidthScale` / `cellHeightScale` | `1.6` | 読み取り枠の大きさ（テンプレートを撮り直さずに微調整する） |
| `codeWidthScale` | `8.0` | ゲームコードを探す幅 |
| `detectSide` | `false` | 黄色の縁取りから自分の側を読むか |
| `dryRun` | `false` | 送らずに本文だけ出す |

### `detectSide` について

**選手の画面では、自分の行に黄色の縁取りが付きます。**
それを読めば「自分がホーム側かアウェイ側か」が分かり、
**Bot が所属と突き合わせて矛盾を検出できます**（完全自動では誰も数字を見ないので、
これが機械に気づける唯一の手がかりです）。

⚠ **既定では読みません。** 側を間違えて送ると、**Bot は観測ごと捨てます。**
**校正できていないうちは `-`（分からない）で送るほうが確実です。**

⚠ **緑の背景は「自分」ではありません。** あれは**ゲーム内で選択している選手**に付くもので、
**運営の観戦では他人の行に付きます。** 使ってよいのは**黄色の縁取り**だけです。

⚠ **運営の観戦では縁取りが出ません**（どちらの側にも居ないため）。

## 自分でビルドする

```
dotnet publish src/Observer -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

.NET 9 SDK が要ります。テストは `dotnet test tests/Observer.Tests` です。

`.github/workflows/build.yml` がタグを打つたびに同じものを作って Release に載せます。

## 中身

| ファイル | 何をするか |
| --- | --- |
| `Capture.cs` | ウィンドウを 1 枚もらう（WGC。**ここだけが素の COM**） |
| `WindowFinder.cs` | 撮る相手を 1 つに決める |
| `Frame.cs` | 画素の入れ物。グレースケール化・縮小・PNG の読み書き |
| `Templates.cs` | テンプレートの読み込みと、正規化相互相関での照合 |
| `ScreenReader.cs` | ラベルから行と列を決めて、数字を読む |
| `Observation.cs` | **CON-09 の 1 行を組み立てる。送る前に検査する** |
| `Webhook.cs` | Discord に POST する |
| `Watcher.cs` | 常駐ループ。**変化が無ければ送らない** |
| `Config.cs` | 設定 |
| `Program.cs` | コマンドの入口 |
